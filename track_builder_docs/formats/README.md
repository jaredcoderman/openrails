# File Formats Reference

Complete reference for all Open Rails file formats used in track building.

## Quick Reference Table

| File Type | Extension | Location | Purpose |
|-----------|-----------|----------|---------|
| Track Database | `.tdb` | `ROUTES/[Route]/tdb.dat` | Master track geometry and node structure |
| Path/Waypoints | `.pat` | `ROUTES/[Route]/PATHS/` | Train navigation waypoints |
| World/Geometry | `.w` | `ROUTES/[Route]/WORLD/` | 3D geometry for rendering |
| Service | `.srv` | `ROUTES/[Route]/SERVICES/` | Links consist + path for activities |
| Activity | `.act` | `ROUTES/[Route]/ACTIVITIES/` | Playable scenario definition |
| Consist | `.con` | `TRAINS/CONSISTS/` | Train composition (engines + cars) |
| Shape | `.s` / `.sd` | `TRAINS/TRAINSET/[Shape]/` | 3D model geometry |

## Format Documentation

### Track & Geometry

#### [Track Database (.tdb)](tdb.md)
Master file containing all track nodes and connections.
- **Use case**: Defines track structure, curves, connections
- **Key concepts**: TrVectorNode, TrEndNode, TrJunctionNode, TrPin, UiD
- **Generated by**: TdbDump
- **Read by**: Open Rails core engine

**Quick structure:**
```
trackdb (
    tracknodes ( count
        tracknode ( id
            [trvectornode | trjunctionnode | trendnode]
            trpins ( inCount outCount ... )
        )
    )
)
```

---

#### [Path Files (.pat)](pat.md)
Navigation waypoints for train movement.
- **Use case**: Defines route waypoints and path linking
- **Key concepts**: TrackPDP (waypoint), TrPathNode (links)
- **Generated by**: TdbDump
- **Read by**: Open Rails path system

**Quick structure:**
```
Serial ( 1 )
TrackPDPs ( count
    TrackPDP ( TileX TileZ X Y Z Flag1 Flag2 )
)
TrackPath (
    TrPathName ( name )
    TrPathNodes ( count ... )
)
```

---

#### [World Files (.w)](world.md)
3D geometry objects for rendering.
- **Use case**: Renders track, scenery, objects in 3D
- **Key concepts**: DynTrackObj, TrackObj, StaticObj, Position, QDirection
- **Generated by**: TdbDump
- **Read by**: Open Rails renderer

**Quick structure:**
```
Dyntrack (
    Tr_WorldFile (
        DyntrackObj ( ... )
        TrackObj ( ... )
        StaticObj ( ... )
    )
)
```

---

### Services & Activities

#### [Service Files (.srv)](srv.md)
Links consist and path together.
- **Use case**: Defines which train and route go together
- **Key concepts**: PathID, TrainConfig
- **Used by**: Activities
- **Referenced by**: Player_Service_Definition

**Quick structure:**
```
Service (
    Serial ( 1 )
    Name ( "Service Name" )
    PathID ( path_file_name )
    TrainConfig ( consist_file_name )
)
```

---

#### [Activity Files (.act)](act.md)
Playable scenario definitions.
- **Use case**: Creates a loadable game scenario
- **Key concepts**: Player_Service_Definition, Events, Weather, Season
- **Loaded by**: Open Rails main menu
- **References**: Services, paths, consists

**Quick structure:**
```
Tr_Activity (
    Tr_Activity_Header ( ... )
    Tr_Activity_File (
        Player_Service_Definition ( ... )
        Events ( ... )
    )
)
```

---

### Train Composition

#### [Consist Files (.con)](consist.md)
Train composition (engines and cars).
- **Use case**: Defines what trains look like and consist of
- **Key concepts**: Engine, Wagon, UiD
- **Referenced by**: Services
- **Uses**: Shape files

**Quick structure:**
```
Consist (
    Name ( "Consist Name" )
    Engine ( shape_name
        UiD ( 1 )
    )
    Wagon ( shape_name
        UiD ( 2 )
    )
)
```

## How Files Reference Each Other

```
Activity (.act)
    ├─ RouteID → Route folder
    └─ Player_Service_Definition → Service.srv
        ├─ PathID → Path.pat
        │   └─ TrackPDPs reference TDB coordinates
        └─ TrainConfig → Consist.con
            └─ Engine/Wagon → Shape files
```

## File Format Overview

### SIMISA Header

All Open Rails text files start with:
```
SIMISA@@@@@@@@@@JINX0X0t______
```

Where X indicates file type:
- `JINX0t0t` = Track Database (.tdb)
- `JINX0P0t` = Path file (.pat)
- `JINX0W0t` = World file (.w)
- `JINX0S0t` = Service file (.srv)
- `JINX0a0t` = Activity file (.act)
- `JINX0C0t` = Consist file (.con)

### STF Format

Files use **SIMISA Text Format (STF)** - a text-based hierarchical format:

```
keyword ( value )
keyword ( value1 value2 value3 )
keyword (
    subkeyword ( value )
    subkeyword ( ... )
)
```

**Rules:**
- Case insensitive for keywords
- Values in parentheses
- Nested blocks for structure
- Comments start with `;`

## Coordinate System Reference

All files use these coordinate conventions:

| Coordinate | Meaning | Range |
|-----------|---------|-------|
| TileX, TileZ | World tile | -13000 to 13000 |
| X, Z | Position within tile | 0 to 2048 (meters) |
| Y | Elevation | Any (meters) |
| AX, AY, AZ | Euler angles | Radians |
| Qx, Qy, Qz, Qw | Quaternion | Normalized |

**Tile System:**
- Each tile = 2048m × 2048m
- Tile (-12842, 14734) = base reference point
- Negative TileX = West, Positive = East
- Negative TileZ = South, Positive = North

## File Size Notes

| Format | Typical Size | Factors |
|--------|-------------|---------|
| .tdb | 50KB-2MB | Number of track nodes |
| .pat | 5KB-100KB | Number of waypoints |
| .w | 10KB-500KB | Number of objects in tile |
| .srv | < 1KB | Very small |
| .act | 5KB-50KB | Activity complexity |
| .con | < 5KB | Very small |

## Common File Patterns

### Empty Blocks
```
keyword ( 0 )
keyword ( )
```

### Lists
```
keyword ( 3
    item ( ... )
    item ( ... )
    item ( ... )
)
```

### Hierarchical Structure
```
outer (
    middle (
        inner ( value )
    )
)
```
